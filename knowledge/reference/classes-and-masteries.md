# Classes and Masteries
> Game version: 1.5.x (Season 5). Last verified: 2026-10-08.
> Labels: **A** asset data (vendored), **G** in-game guide, **X** Maxroll/community 2026, **U** unverified/stale.

## Summary
- 5 classes (`classID` 0-4), each with a base class plus 3 masteries (`masteryIndex` 1-3; index 0 = the unspecialised base class). 15 masteries total (A).
- Passive tree ids: `pr-1` Primalist, `mg-1` Mage, `kn-1` Sentinel (internal tree name "Knight"), `ac-1` Acolyte, `rg-1` Rogue (A).
- All classes share identical base numbers (health, mana, regen, stun avoidance, endurance); only starting attributes differ (A, table "Per-class differences").
- Max level 100 (G). Passive points: 98 from levels 3-100 (G) + up to 15 from quests/first dungeon clears = 113 max (X). Skill specialisation slots: 5, unlocked at character levels 4/8/20/35/50 (G, X).
- Mastery is chosen after the Mastery quest; base-class tree points can exceed 20; a character can allocate points in the base class tree and in ALL THREE mastery trees, but in the non-chosen masteries only the first half (nodes with `tree_nodes.mastery_requirement` 0-20); the upper half (requirement 25-45) is exclusive to the chosen mastery (X; see "Mastery access rule"). There is no gate flag in the data: the split is the `mastery_requirement` value, found from 205 community profiles (X).
- 136 class skills exist (A, derived from `classes.json`): each class has 1 starting skill, 7-8 character-level unlocks, 4 base-tree unlocks and 5 skills per mastery (1 mastery skill + 4 tree-point unlocks).
- Season 5 added the last 3 class skills: Radiant Lance (Paladin), Summon Tide Elemental (Shaman), Dreamslash (Bladedancer) (X, verified in A).
- Mechanics that use these numbers (health/mana formulas, minion scaling) are specified in `../mechanics/stat-model.md` and `../mechanics/minions.md`.

Formulas from `classes.json` (A):
- `Health = RoundHalfEven((baseHealth + L*healthPerLevel + Σadded) * (1+Σinc) * Π(1+more))`; `Mana` same with `manaPerLevel`; `HealthRegen = (healthRegen + L*healthRegenPerLevel + Σadded) * (1+Σinc) * Πmore`.
- `StunAvoidance = baseStunAvoidance + L*stunAvoidancePerLevel (+ mods)` = 250 + 5L.
- `EnduranceThreshold = (1+inc)*((maxMore + enduranceThresholdPerHealth + added) * maxHealth + baseEnduranceThreshold + L*enduranceThresholdPerLevel + added) * more` with `enduranceThresholdPerHealth` 0.2 (= 20% of max health).

Conflict: the in-game guide text says +8 health and +0.125 health regen per level in one paragraph and +10 health in another (G, `Levels_1` vs `HealthAndRegen_1`); asset data says +10 health and +0.14 regen per level (A). Use A.

## Passive points and tree structure

- Passive point sources: 1 per level from level 3 to 100 = 98 (G `Levels_2`); up to 15 quest-reward points; maximum total 113 (X `maxroll_passives-and-skills.md`). First completion of a dungeon grants 2 passive points and 1 idol slot (G `Dungeons_Paragraph_4`); the world map caps the total obtainable quest rewards, and more quests than the cap offer them (G `WorldMap_Paragraph_11`).
- Season 5 quest changes (X patch notes): defeating Majasa and The Observer no longer gives +1 to all attributes; collecting 5 Knowledge of Orobyss now gives +2 to all attributes; defeating The Observer gives +1 passive point.
- Every class has a base tree plus 3 mastery trees (X). Tree node counts (A, `passiveTree.nodesPerMastery`) are in the class table above; totals per tree are 103-111 nodes.
- Mastery trees unlock after the Mastery quest (X). "You can allocate passives on the first half of all masteries regardless of the one you chose but the second half is only available for the one you picked" (X). Points beyond 20 may be put in the base tree (X).
- Node unlock progression: each node has `masteryRequirement` = points that must already be spent in the tree (the "golden progress bar") (A field, X meaning). Observed values: base tree 0-25 in steps of 5; mastery panels 0-45 in steps of 5 (A):

## Mastery access rule

**Rule (X; the cut-off value is derived from guide data, not stated by the game files).** A character can spend passive points in the base class tree and in all three mastery trees of its class. In a mastery that is not the chosen one, only the nodes below the mastery gate are reachable, which in the data is `tree_nodes.mastery_requirement` of 20 or less (the first five of the ten requirement steps 0, 5, ..., 45). The nodes with a requirement of 25-45 (the second half) can be taken only in the chosen mastery. Example: a Void Knight can take Forge Guard and Paladin nodes up to requirement 20, such as Champion of the Forge (requirement 15) and Crushing Blows (requirement 20), but not their requirement 25+ capstones. Confidence: Maxroll's wording (quoted above) is **X**; `mastery_requirement` as the points that must already be spent in that tree is **A** (field) / **X** (meaning); the "<= 20" cut-off is **X** derived (below), the exact in-game cut-off is **U**.

What the data exposes for the gate. `tree_nodes` has `mastery` (0 base class, 1-3 the mastery panel the node sits in), `mastery_requirement` (0-25 on the base tree, 0-45 on a mastery panel) and `lock_node` / `base_lock_node` (both 0 on every class-tree node, so they are not the gate). There is no "locked to chosen mastery" flag or "points in mastery" column other than `mastery_requirement`. The evidence for the cut-off is the community builds (74 Maxroll guides, 1.5.2): across 205 profiles that spend points in a mastery they did not choose (up to 38 points in one such mastery, 4,614 points in total), the highest `mastery_requirement` ever allocated is 20; in the chosen mastery it reaches 45 (228 profiles). A pure points cap would have produced nodes with requirement 25 for the profiles that spent more than 25 points, so the limit is a node gate, not a point cap.

Nodes of the other two masteries that a Void Knight can reach (parameters: class name, chosen mastery; 32 rows: 16 Forge Guard, 16 Paladin; run on the 1.5.2 database, returns Champion of the Forge `kn-1:111` and Crushing Blows `kn-1:36`):

```sql
SELECT ms.name AS mastery, n.node_id, n.name, n.max_points, n.mastery_requirement
FROM tree_nodes n JOIN trees t ON t.tree_id = n.tree_id AND t.tree_kind = 'class'
JOIN classes c ON c.class_id = t.class_id AND c.name = 'Sentinel'
JOIN masteries ms ON ms.class_id = c.class_id AND ms.mastery_index = n.mastery
WHERE n.mastery > 0 AND ms.name <> 'Void Knight' AND n.mastery_requirement <= 20 ORDER BY n.mastery, n.mastery_requirement, n.node_id;
```

The community evidence (highest requirement allocated, inside vs outside the chosen mastery):

```sql
SELECT v.mastery = p.mastery_index AS in_chosen_mastery, count(DISTINCT v.build_profile_id) AS profiles,
       max(tn.mastery_requirement) AS max_requirement_allocated, sum(v.points) AS points
FROM v_build_nodes_named v JOIN community_build_profiles p ON p.build_profile_id = v.build_profile_id
JOIN tree_nodes tn ON tn.tree_id = v.tree_id AND tn.node_id = v.node_id
WHERE v.kind = 'passive' AND v.mastery > 0 AND tn.tree_kind = 'class'
GROUP BY 1 ORDER BY 1;
```

Worked check: Maxroll's Erasing Strike Void Knight (slug `erasing-strike-void-knight-guide`, default tab) spends 20 points in the base Sentinel tree, 68 in Void Knight (highest requirement 45) and 25 in Forge Guard (highest requirement 20), among them Battle Hardened 8, Unflinching 5, Champion of the Forge 5 and Crushing Blows 5 (X, `v_build_nodes_named`). Use this when planning: a build may take the defensive first half of a second mastery (Forge Guard block, armour and fire/physical resistance nodes) without leaving its mastery.

## Pitfalls
- `classID` order (Primalist 0, Mage 1, Sentinel 2, Acolyte 3, Rogue 4) differs from the internal tree-name order (Knight, Acolyte, Mage, Primalist, Rogue); Sentinel's passive tree is named "Knight" with id `kn-1` (A).
- `masteryIndex` 0 means the base class, not "no data": mastery 1-3 ids are shifted by one relative to a 0-based list of the three masteries.
- Mastery-panel node data marks every node of a panel with `requiredMastery` equal to that panel (A: e.g. kn-1 mastery 1 has 31 nodes all `requiredMastery`=1), which does not by itself express the "first half is open to all masteries" rule stated by Maxroll (X). No flag in `tree_nodes` marks the gate (`lock_node` and `base_lock_node` are 0 on all 541 class-tree nodes); the practical split is `mastery_requirement <= 20` (see "Mastery access rule", X). Do not read `mastery` or `requiredMastery` as "only the chosen mastery may use this node".
- Level thresholds of mastery skills are passive points spent in that tree, not character levels; the `unlockableAbilities[].level` numbers are character levels (inferred).
- Guide text vs asset: per-level health (8 vs 10) and regen (0.125 vs 0.14); minion scaling (0.6% vs 0.8%). Prefer A.
- Maxroll "exclusive skills" lists name only some of each mastery's skills; the others are still listed under the mastery in `classes.json` and are unlocked by tree points. Whether another mastery of the same class can use them is not stated in any source (U).
- Minimum skill level unlock levels differ: G lists 8/12/17/24/32/40/50/60/70; Maxroll (2026-04-02) lists 10/15/20/30/40/50/60/70/80 with a cap of 10 (X). G is the 1.5.0 text; treat X as unverified.

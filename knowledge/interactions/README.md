# knowledge/interactions

A curated catalogue of unintuitive, build-defining mechanics interactions in Last Epoch 1.5.x (Season 5, "Rage of the
Frostborn"). It exists for an AI build-planning agent: the interactions here are the ones a model reasoning from tooltips
alone tends to miss, and they are the raw material for finding unusual but viable builds.

## Files

| File | What it is |
|---|---|
| `catalogue.md` | Hand-written entries, grouped into 11 sections (conversion, triggers, minions, ward, ailments, defences, double-dipping, attribute/resource scaling, build-enabling uniques, Season 5, traps). Every entry cites a source. |
| `unique-effects-index.md` | Generated table of all 489 uniques in the vendored data: id, name, base type, tooltip text (or effect names and visible mods when the data has no tooltip), and which planner model in `unique_effect_models.json` covers each special effect. Use it to look up an item the user drops. A short hand-written "Notes" section after the table clarifies rules for a few rows (Harbinger of Stars, Snowdrift, Morditas' Reach, the two potion cleanses, Mask of Indifference). |

The index is generated by a node script (`build-unique-index.js`, not vendored; reproducible from the stated logic)
from `vendor/lastepochbuilder/research/data/game/uniques.json`, `.../unique_effects.json` and
`vendor/lastepochbuilder/client/data/unique_effect_models.json`. Do not edit it by hand; regenerate it after a data refresh.

## Entry format (catalogue.md)

```
### <short name>
- **Tags:** comma list from the fixed tag set below
- **Rule:** one to three sentences: what interacts with what, and the mechanical result, with numbers when known.
- **Why it matters for builds:** one or two sentences.
- **Involved:** uniques / skills / nodes / affixes by name, with ids when the data has them.
- **Confidence:** label + source(s) (repository-relative file path or URL).
```

Id conventions inside entries: `uid N` = uniqueID in `uniques.json`; `PP N` = PlayerProperty index (key in the `player`
map of `unique_effect_models.json` and in `ppFormulas` of `unique_effects.json`); `AP a:p` = AbilityProperty (ability index :
property index, key in the `ability` map); affix numbers are `affixId` in `vendor/lastepochbuilder/research/data/game/affixes.json`.

### Tag set

conversion, trigger, proc, minion, totem, companion, ward, mana, health, leech, ailment, dot, crit, penetration, shred,

## Confidence labels

The first label in the Confidence line is the entry's primary confidence; extra labels name supporting sources.

| Label | Meaning | Typical source |
|---|---|---|
| **D** | Derived from decompiled game code, via the weksil research and models. A trailing `D?` in the text means the structure was read from code but a constant or the exact semantics came from the tooltip. | the `07*` notes in `vendor/lastepochbuilder/research/`, `unique_effects.json`, `unique_effect_models.json`, `conditional_defenses.json`, `item_procs.json`, `client/docs/ENGINE.md` |
| **A** | Read from extracted game asset data (tables, tooltips, affix tiers) or an official formula image. | `uniques.json`, `affixes.json`, `attributes.json`, `skill_conversions.json`, `weaver_node_effects.json`, `research/02_le_formulas.md` |
| **G** | Stated by the in-game Game Guide text shipped with 1.5.0. | `vendor/lastepochbuilder/research/02_assets/ingame_gameguide_en_v1.5.0.txt` (keys `GameGuide.*`) |
| **X** | Community-verified or official 2026 source: Maxroll pages updated in 2026, the Season 5 patch notes. | maxroll.gg URLs |
| **U** | Unverified or old (pre-1.4) community claim that no 2026 source or data confirms. Marked "may be outdated". | old forum threads |

Prefer D and A over X, and X over U. When a tooltip and the code disagree (several entries note this), the code value is
what the game does.

## How an agent should use this when brainstorming

1. **Scan by tag, not by section.** Pick the tags that describe the idea you are exploring and read every entry carrying
   them. Useful entry points:
   - damage type or delivery change: `conversion`, `tag-matching`
   - proc and repeat engines: `trigger`, `proc`, `cooldown`, `charges`, `channel`, `movement`
   - summoners: `minion`, `totem`, `companion`, `aura`
   - defence layers: `ward`, `endurance`, `block`, `dodge`, `armour`, `defense`, `leech`, `health`, `mana`
   - DoT and debuffs: `ailment`, `dot`, `shred`, `penetration`, `curse`, `freeze`, `chill`, `shock`
   - multipliers and weird scaling: `double-dip`, `scaling-oddity`, `crit`
   - gear systems: `idol`, `legendary`, `set`, `weaver`
2. **Chain entries.** The strongest ideas combine a converter with an engine, for example: Eternal Font (potion every second)
   with any "on potion use" unique; Flesh of Stone (health capped at endurance threshold) with mana-as-threshold; the low-life
   ward engine with Twisted Heart or Chronostasis; Frostborn Solitude's healing penalty with a leech or regen build that
   Increased Healing never touched.
3. **Check traps before recommending.** Read every `anti-synergy` entry whose other tags overlap the plan (no-ward-gain
   items, immunities that block self-ailments, the one-primordial limit, one-of-each unique idols, damage-taken conversions
   above 100%).
4. **Respect confidence.** Present D and A rules as facts, X as current community knowledge, U only as a hypothesis to test.
   When an entry carries `D?`, tell the user the in-game behaviour should be confirmed.
5. **Look up items in the index.** When the user names or drops a unique, find its row in `unique-effects-index.md`, read the
   tooltip and model column, then search the catalogue for its uid or name to see known interactions.

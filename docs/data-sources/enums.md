# Enums, bitmasks and coded values

Every entry below states the evidence it was derived from. Status labels:

- **PINNED**: fully resolved, every value has a name and evidence.
- **PARTIAL**: some values resolved, remaining ones marked *unknown*.
- **OBSERVED**: only the set of values in the data is known.

Evidence sources: the LE Tools enum globals (`AT`, `SP`, `LocalSP`, `AilmentID`, `UIBuffIds`, `BuffId`, `BuffPropId`, `CustomConditionType`, all in the `db` and `planner` files, see [letools.md](letools.md)), the cross-source joins in [ids.md](ids.md), the English strings in `en.json`, and English text embedded in the Maxroll data. Numbers (counts) come from the scripts named in [README.md](README.md#scripts); the tables in this file were generated by `enum_tables.js`, `tag_check.js` and `misc_frag.js`.

## 1. Damage array order

**Status: PINNED.** Wherever a `damage` array appears (`baseDamageStats.damage` / `baseDamage.damage` in abilities, ailments, entity actors, Maxroll `abilities[*].components[].baseDamageStats.damage` and `ailments[].baseDamage.damage`) it has exactly **7** slots in this order:

| index | damage type |
|---|---|
| 0 | Physical |
| 1 | Fire |
| 2 | Cold |
| 3 | Lightning |
| 4 | Necrotic |
| 5 | Void |
| 6 | Poison |

The same order is used by `additionalPenetrationDamageType` on ailments (Ignite = 1 Fire, Bleed = 0 Physical, as in the Ignite and Bleed examples in [letools.md](letools.md)) and by `penetration[]`. Note that this index order is **different from the bit order of the `AT` tag bitmask** (section 2: Physical, Lightning, Cold, Fire, Void, Necrotic, Poison).
